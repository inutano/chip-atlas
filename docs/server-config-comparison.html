9. パフォーマンス (実測)

各インスタンスの localhost からのレスポンス時間 (nginx → Puma)。コールドキャッシュ時の 1 回測定。

エンドポイント 旧構成 (t3.medium) 新構成 (t4g.medium)
/health 248 ms 9 ms
/ (ホームページ) 50 ms 50 ms 同等
/peak_browser 1.8 ms 2.0 ms 同等
/api/genomes 1.3 ms 1.4 ms 同等
/health の差異について: 旧構成の 248 ms は Puma が起動直後のウォームアップ状態だった可能性があります。定常状態ではほぼ同等と予想されますが、新構成の Graviton CPU は整数演算で Intel Xeon に匹敵する性能を ~20% 低コストで実現します。

10. まとめ

カテゴリ 改善点
コスト t4g.medium (Graviton) で月額 ~$13 削減 (37.4 → 24.5 USD)
再現性 AMI の累積変更に依存せず、スクリプト 1 本で 0 から構築可能
セキュリティ systemd サンドボックス、SELinux 利用可能
運用性 systemd による自動再起動・journald ログ統合・ワンコマンド再デプロイ
同時処理 Unicorn 2 → Puma 10 (2 ワーカー × 5 スレッド)
OS サポート Ubuntu 22.04 (EOL 2027-04) → Amazon Linux 2023 (EOL 2028)
クリーンさ 旧 Ruby バージョン・Unicorn 残骸・stash なし。ディスク使用率 57% → 10%
注意: 旧構成の「本番 AMI」は Unicorn + init.d で運用されていたものであり、今回の旧インスタンスではその上に Puma + systemd を追加導入しています。本レポートの「旧構成」列は AMI 由来の設定を主に記載しています。
